# 实验协议

先核验实现，再比较能力。当前仓库不包含经过独立业务测试集确认的提升数字。

1. 按图像源、视频源和事件分组划分 train/dev/test，保存 manifest 哈希、去重结果与规则版本。相邻帧不能跨 split；错例回流只允许训练集。
2. 固定 backbone、token 预算、优化器、训练步数、随机种子。比较全局损失、增加区域损失、再增加难负例；报告区域检索 Recall@K、属性区分准确率及分风险类别召回。
3. 固定数据和输出协议比较 SFT 初始化与 GRPO；单独报告类别正确率、漏检、误检、解释与图像证据一致性，不以总奖励替代能力指标。
4. 固定视频总 token 预算，比较均匀抽帧与覆盖/变化量抽帧，报告短事件召回。记录每批有效 token 比例、峰值显存、吞吐和通信耗时；不从通信轮数推断速度。
5. 至少三个种子，开发集选模型，测试集一次汇报；保存配置、环境、checkpoint、原始预测和逐例评分。

发布中的 CPU 测试解决正确性问题。真实预训练权重、经授权的业务数据、GPU 登录与完整训练后端就绪后，才能执行能力对比并决定继续、修改或停止。
